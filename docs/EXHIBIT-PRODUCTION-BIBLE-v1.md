WHAT AN EXHIBIT IS
A small interactive teaching tool that (1) looks great behind Lee in a Cram Blast, (2) rewards a deeper pass in Review, and (3) survives being handed to a student alone with zero instructions. Not a slide. Not an app. The digital version of what a great tutor does with a marker.
THE RULE SANDWICH (extracted from the Canva library — Lee's core grammar)
Every concept renders as:

1. NAME CHIP — the concept's name, prominent (+ AKA alias when professors use a second name: "Expense Recognition (AKA Matching)")
2. THE RULE — one bolded sentence, with THE PHRASE THAT ANSWERS THE EXAM QUESTION visually highlighted (the old decks used yellow; use our highlight treatment)
3. THE EXAMPLE — one concrete, everyday case (landscaper, software subscription). Example follows rule, always, immediately.

TEN LAWS

1. ONE CONCEPT PER SCREEN. If two ideas compete, split or layer.
2. HIGHLIGHT = THE ANSWER. Whatever gets visual emphasis should be the phrase a CEQ will ask for. Emphasis is exam-targeting, not decor.
3. SHOW THE TRAP NEARBY, MUTED. (Canva pattern: Cost $200k highlighted beside Market $250k / Salvage $80k unhighlighted.) The wrong answers sit in plain sight so Lee can point at them.
4. PROGRESSIVE REVEAL IS THE DEFAULT. Authored reveal steps on the film controller (Tab next / Shift+Tab back / \` reset). Nothing visible before Lee has said it. Full-reveal state exists for student free-exploration.
5. SPOTLIGHT IS SHARED INFRASTRUCTURE. Click = illuminate selection, mute the rest, ALWAYS preserving enough context to see position. Interaction must reproduce a tutor's finger — if a click doesn't change what a student attends to, cut it.
6. TEXT DIET. One-word anchors (OWN/OWE/VALUE/EARN/COST). Reveals ≤2 lines. If Lee will say it on camera, the exhibit doesn't print it. The exhibit communicates structure silently; Lee supplies the words.
7. IMPORTANCE CUES, THREE LEVELS, SUBTLE: MUST KNOW · EASY POINT · A+ DETAIL. Small corner tags, consistent placement, dismissible. A+ DETAIL is also the professor-dependent flag ("check your professor's slides").
8. CONFIG, NOT CODE. An exhibit's content (chips, definitions, examples, reveal order, importance tags) lives in a config object. New content = config edit. Accuracy fixes = config edit.
9. ACCURACY AUDIT BEFORE SHIP. Old slide claims get verified; absolutes get softened only where wrong ("always recorded at cost" → "recorded at cost when acquired"); professor-variable classifications get an A+ DETAIL tag instead of a silent ruling. Never academically bloat — intro-course useful beats technically exhaustive.
10. KRUG TEST + FILM TEST TO SHIP: a student understands what to click and what the visual means without being told; the exhibit looks intentional in an OBS capture at every state; film-mode rules hold (locked geometry, keyboard isolation, zero chrome in Recording Mode); works 16:9 canonical, degrades gracefully at mobile widths.

INTERACTION VOCABULARY (reuse before inventing)
COMPARE (two mirrored sides) · CONCEPT+EXAMPLE (rule-sandwich card deck) · MAP/FLOW (ordered sequence, orbiter) · CLASSIFIER (chips into categories) · CHEAT SHEET (dense reference) · SCENARIO (one transaction explored) · BRANCH MAP. Plus primitives: mode chips, spotlight, reveal sequences, zoom-with-breadcrumb, node declarations (future drag). A new interaction pattern must justify itself against these.
THE LOOP EVERY EXHIBIT SERVES
CRAM BLAST: flash it early → blast CEQs → return, reveal one more layer → encourage → out. REVIEW: slow manipulation of the same exhibit, possibly across several short videos (one exhibit-lesson each). STUDENT: the exhibit persists in the player as a tool. One source exhibit; 16:9 canonical; derivative reframes are a later human/AI workflow, never a constraint on the canonical design (when two layouts tie, prefer the one that reframes better).
VOICE
The product's UI copy stays minimal and professional-casual so Lee's on-camera personality does the talking. No manufactured slang, no "Welcome, learners." The exhibit is the straight man; Lee is the show.
CONVEYOR
One exhibit per Claude Code prompt: research existing primitives → build → test → visual QA (desktop + mobile + OBS capture) → commit → merge → deploy per the EXISTING workflow. Excellent-and-shipped beats perfect. Every completion ends by naming the next exhibit.
